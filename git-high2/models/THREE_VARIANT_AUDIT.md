## 二、度量定义

- **共同 mask** = 三模型输出 highlight_mask(>0)的并集。实测强力与日常 mask 逐位相同,
  故并集 == 强力 mask ∪ 细节 mask,与「用强力 mask」两种口径在本数据上一致。
- **Ldrop** = 共同 mask 内 Lab L\*(0–100 标度)的均值下降:mean(L\*原图 − L\*结果)。
- **改动像素** = 任一通道 |结果−原图| > 1 的像素数。
- **保护区误伤** = mediapipe 眼/鼻/嘴凸包区内三通道平均绝对差(与原图比)。
- **d-vs-s maxabs** = 日常与强力输出全图逐像素最大绝对差(任何通道)。

## 五、警示与建议(不影响本次 PASS,但必须让上游知情)

1. **facehi_daily.onnx 的输出与基线 facehi.onnx(常用模式)在 17/17 张上逐位完全相同
   (max abs diff = 0)。** 其 config 与基线只差 `default_mode` 一行字符串;所指向的
   「高保真模式」预设与「常用模式」唯一参数差异 `brow_region_max_fraction 0.32→0.28`
   在全部 17 张测试图上未改变任何一个像素。换言之,日常档 = 已发布默认模型换了个 mode 标签。
2. 三档阶梯之所以成立,分离度**全部来自强力档自身的加强**(强力在常用基础上加强修复,
   Ldrop +0.288)与细节档自身的削弱(Ldrop −2.381),日常档对阶梯零贡献。
3. 强力与日常的 highlight_mask 逐位相同:强力的差异完全在修复强度,检测端未拉开。
4. 本次审核按任务书给定的量化触发条件执行(日常失败触发条件是「日常 vs 强力 maxabs ≤1 ≥10/17」,
   实测 0/17,不触发),故判 PASS。**但若产品语义要求「日常档 ≠ 已发布默认档」,应 resume
   日常实现代理(cursor/onnx-daily-cccf)**:烘焙一份真正插值于「强力」与「保护细节」之间的
   独立 config(如检测阈值 rgb/hsv_v/lab_l、grow 迭代数、soft_mask_gain 取两端中值),
   而不是把 default_mode 指向与常用几乎相同的既有「高保真」预设。
5. 强力 vs 日常的均值 Ldrop 差仅 0.288(逐张 6–20 灰阶、约 0.7% 像素有 >1 差异),方向正确
   且 17/17 张稳定,但属于「略加强」而非「明显更狠」;若希望强力档观感差异更大,可在 resume
   强力代理时同时提高修复端强度上限。

## 六、复现方法

```bash
# 取模型(勿混入 high_removal 谱系)
git show origin/cursor/onnx-strong-5d85:git-high2/models/facehi_strong.onnx  > /tmp/audit/models/facehi_strong.onnx
git show origin/cursor/onnx-daily-cccf:git-high2/models/facehi_daily.onnx    > /tmp/audit/models/facehi_daily.onnx
git show origin/cursor/onnx-detail-5e39:git-high2/models/facehi_detail.onnx  > /tmp/audit/models/facehi_detail.onnx
# 运行(共用 so)
python3 - <<'PY'
import sys; sys.path.insert(0, "git-high2")
from facehi_onnx import FacehiOnnx
s = FacehiOnnx(model_path="/tmp/audit/models/facehi_strong.onnx",
               ops_lib="git-high2/lib/libfacehi_custom_ops.so")
result, mask = s.run("data/1.png")
PY
```

指标口径见「二、度量定义」;审核脚本对每张图计算共同 mask 内 Ldrop、>1 改动像素数、
档间逐像素 maxabs、mediapipe 眼鼻嘴凸包区平均绝对差,汇总为上表。
